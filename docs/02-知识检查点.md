# 知识检查点清单

用法:每个检查点配一个"操作题"。能做出操作题 = 懂了。做不出 = 别往下走。
这不是理论考试,是确保你有**可操作的心智模型**,能预测 agent 行为、定位故障。

---

## Token 与 Context Window

### 概念
- token 是什么?和字符/词的关系?
- context window 是什么?input token 和 output token 算在同一个 window 里吗?
- 超出 context window 会发生什么?(截断?报错?模型失忆?)

### 操作题
1. 用 tokenizer 工具,算出你 system prompt + 一段对话占多少 token。
2. 在你的 agent 里故意塞一个超长 prompt(超过模型限制),观察报错形式。
3. 能回答:你的 agent 跑 10 轮工具调用,context 会怎么增长?大概什么时候爆?

---

## Sampling(采样参数)

### 概念
- temperature 是什么?0 和 1 和 2 的区别?
- top-p 是什么?和 temperature 的关系?
- 为什么**工具调用场景通常用低 temperature**?

### 操作题
1. 同一个 prompt,temperature=0 跑 5 次,看输出是否一致。
2. temperature=1.5 跑同一个需要工具调用的 prompt,观察模型是不是开始乱调工具或不调。
3. 能回答:做 agent 时你默认会用什么 temperature?为什么?

---

## Function Calling / Tool Use 协议

### 概念
- 模型怎么"知道"有哪些工具?(答:你传的 tools schema)
- 模型返回 tool_call 时,它返回的是什么结构?(name + arguments)
- tool 的结果以什么 role 喂回模型?(tool role / 对应 provider 的约定)
- 为什么需要 `tool_call_id`?

### 操作题
1. 把你 agent 的 `tools` 参数打印出来,读懂每个字段。
2. 故意把工具 schema 的 description 写得很模糊,看模型调用准确率下降。
3. 能回答:工具的 description 写得好不好,怎么影响 agent 质量?

---

## Streaming(流式)

### 概念
- SSE / chunk 是什么?为什么需要流式?
- 流式时,一段完整的内容是怎么由多个 chunk 拼出来的?
- 流式时 tool_call 为什么会"分片"到达?怎么攒齐?

### 操作题
1. 把流式返回的每个 chunk 打印出来,看它的结构。
2. 在你的 agent 里实现:流式收集 text,同时攒齐分片的 tool_call。
3. 能回答:流式中途网络断了,你的 agent 状态会变成什么样?

## 上下文管理(Phase 2 重点,Phase 1 先建立直觉)

### 概念
- 为什么长对话会让模型"变笨"?(注意力被稀释 / 关键信息被挤掉)
- context 压缩有哪些策略?(截断旧消息 / 摘要 / 滑动窗口)
- 压缩的代价是什么?(丢信息)

### 操作题(Phase 1 版)
1. 让你的 agent 跑 20 轮对话,观察它是不是开始"忘事"或答非所问。
2. 能回答:你的 agent 现在用什么策略管 context?它的上限大概多少轮?

---

## Embedding 与检索(Phase 3 重点,先建直觉)

### 概念
- embedding 是什么?它把文本变成了什么?
- 为什么"语义相近"的文本,embedding 向量也相近?
- cosine 相似度在算什么?

### 操作题(Phase 1 预习,不强求)
1. 找一个 embedding API,把三句话("猫在睡觉"/"小猫打盹"/"今天股市大涨")各自 embed。
2. 算两两 cosine 相似度,验证前两句分数更高。
3. 能回答:为什么 RAG 要用 embedding 而不是关键词匹配?

## 如何使用这份清单

- **不要一次性全看**。跟着 `03-Phase1-逐日任务.md` 的节奏,到了对应天数再看对应章节。
- **操作题必须做**。看懂概念 ≠ 会用,做出操作题才算懂。
- **做不出的题就是你的盲区**,标记出来,阶段复盘时优先补。
