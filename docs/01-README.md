# Agent 学习计划

目标:一年内成为有判断力的 agent 开发者,支撑副业产品化。
节奏:每天 1 小时,约 365 小时。
核心原则:**判断力优先**。手写机制的核心循环是为了建立判断力,不是为了写代码本身。

## 核心原则:分层使用 AI

| 内容 | 做法 |
|---|---|
| 核心机制(agent loop / 状态机 / 工具协议 / 检索原理) | 手写一遍,理解机制。不可省。 |
| 应用层、样板、重复劳动 | 用 AI,这本来就是 AI 该干的 |
| 读源码学设计 | 自己读、写笔记,AI 可解释但结论自己下 |

每个机制的毕业测试:闭卷能默写核心循环 + 口述 3 个易踩的坑。通过 = 这类代码以后交给 AI。

2. **标题用汉字**:所有文档的一级标题统一用汉字(可用「 —— 」分隔副标题)。

4. **commit message 用汉字**:如 `文档:新增 Phase1 逐日任务`。**严禁自动提交**(不写脚本/钩子自动 commit,所有提交由人手动执行并核对 `git status`)。

## 阶段总览(依赖链)

```
Phase1 地基 → Phase2 精读 → Phase3 RAG → Phase4 多agent → Phase5 框架
```

每阶段是下一阶段的前置。**不要跳阶段**,在烂地基上叠楼是最常见的翻车。

| Phase | 周期 | 名称 | 语言 | 商业等级 |
|---|---|---|---|---|
| 1 | W1-4 | 撕开黑箱:从零写最小 agent | Python | Lv1 |
| 2 | W5-8 | Coding Agent 深度:精读 pi 源码 | 读 TS | Lv2 |
| 3 | W9-14 | RAG 与检索工程 | Python | **Lv3** |
| 4 | W15-19 | 多 Agent 与工作流编排 | Python | Lv3 |
| 5 | W20-24 | 框架设计:造自己的框架 | Python | Lv4 |
| 6 | 持续 | 副业产品化(从 Phase 3 起) | - | - |

### 商业等级标尺

| 等级 | 含义 |
|---|---|
| Lv0 | 补地基中,不要收费 |
| Lv1 | 可接零散小活(自动化脚本、代码审查) |
| Lv2 | 标准化 agent 搭建服务 |
| **Lv3** | **主要商业解锁点:可做 RAG 产品/定制 agent** |
| Lv4 | 架构咨询/自研产品 |
